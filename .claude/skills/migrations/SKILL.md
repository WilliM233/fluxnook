# Migrations

## One folder

`supabase/migrations` is the only migration folder. drizzle-kit writes into it (`drizzle.config.ts` `out`, `prefix: "supabase"` for the timestamp names the CLI applies); the Supabase CLI applies it.

## Generate, never migrate or push

- Table changes: edit `src/db/schema.ts`, then `npm run db:generate -- --name=<what_changed>`.
- Hand SQL (triggers, functions, grants): `npm run db:generate -- --custom --name=<what_it_does>`, then fill the empty file. Going through `--custom` keeps drizzle's journal in step.
- Never `drizzle-kit migrate` or `drizzle-kit push`. They keep a second ledger the Supabase CLI doesn't know about.
- `npm run db:check` is the proof that schema and SQL agree: `drizzle-kit check` on the snapshots, then a `generate` against a copy under `node_modules/.cache` that must write nothing. It never writes to the repo; CI runs it on every PR.

## Every file opens with its reversal

The Supabase CLI has no down migrations. Each file starts with a comment saying what it is and a `-- Down:` block holding the SQL that undoes it, in order. If a later migration depends on it (a trigger inserting into its table), the header names which Down must run first. If it can't be undone, the header says why. Before committing, run the down SQL inside `begin; ... rollback;` against local to see it works.

## Applying locally

`npx supabase db reset` drops local, applies every file in order, and re-runs the seed. Never create anything by hand in Studio: a reset loses it.

## `supabase/migrations/meta/`

Generated by drizzle-kit. Never hand-edit it. Biome skips it (`biome.json` `files.includes`).

## The Data API stays off app tables

RLS is off, so two lines in `supabase/config.toml` `[api]` keep the publishable key away from app tables (ch 0.2 Q1 b, S6):

- `schemas` leaves out `public`, so PostgREST serves nothing from it.
- `auto_expose_new_tables = false`, so a table created in a migration gets no `select`, `insert`, `update` or `delete` for `anon` or `authenticated`. Without it, pg_graphql (on by default on hosted projects) would serve the table even with `public` out of `schemas`.

App tables are reached only through `/api/v1`. Never `grant` a table to `anon` or `authenticated`, and don't put `public` back in `schemas`. The hosted project needs both settings when it exists. `tests/e2e/rummage-graphql-exposure.spec.ts` checks the GraphQL side locally.

## Visibility

Every table that holds user content gets a `visibility` column, private by default (`CLAUDE.md`). Account tables don't: `profiles` has none (ch 0.2 Q2), and its migration header says so.

As of Ch 1.1, five tables carry `visibility` (`text not null default 'private'`, checked to `private`/`unlisted`/`public`): `shelves`, `shelf_entries`, `occurrences`, `journal_entries`, `copies`. Three carry `owner` → `profiles` on delete cascade: `shelves`, `occurrences`, `copies`. The rest reach their owner through a parent: `shelf_sections` and `shelf_entries` through their shelf, `journal_entries` through its occurrence. `shelf_sections` has no `visibility`; the shelf's is the section's. The catalog tables (`items` and its children, `editions` and theirs, `franchises` and theirs) carry neither: they're shared by every user. A new content table gets both the column and its `<table>_visibility` check, plus `owner` or a parent that has one, and `tests/unit/schema.test.ts` names it.

Every table but `profiles` has `updated_at`, kept by `public.set_updated_at()` through a `<table>_updated_at` trigger (`20261023195411_updated_at.sql`). A new table adds its trigger in a `--custom` migration; the constraint test fails on a table without one. A `--custom` file may also write outside `public`, as `20261024180430_covers_bucket.sql` does to `storage.buckets` (Ch 1.2); `db:check` never sees it, so its Down is the only proof it reverses.

## Triggers on `auth.users`

Functions a trigger on `auth.users` calls are `security definer` with `set search_path = ''` and schema-qualify every name. The insert into `auth.users` runs as `supabase_auth_admin`, which has no grants on `public`.
