## 0. Spec (Nookkeeper)

**What this chapter delivers.** The second provider, and the first one for the shelf you can touch. Signed in, you search Open Library for a book from the same box that searches TMDB, see which results are already in your catalog or look like one you have, and add one; the cover comes with it. Type an ISBN off the back of a book instead and the box shows that one edition: publisher, year, pages, format, and whether the work it belongs to is already yours. Adding it puts the work in the catalog if it isn't there and records the printing under it, so the physical library has something to point at when copies arrive in 1.7. The King books in the fixture, which have no provider yet, get their Open Library details attached rather than duplicated. No key is needed: book search works on a fresh clone.

**Acceptance.**

Nothing else changes shape: the ISBN is an `edition_sources` row with source `isbn`, and Open Library ids are `item_sources` / `edition_sources` rows with source `openlibrary`. Appended, not folded (the 1.2 migrations have reached `dev`); reversible. `db:check` clean; `fixtures:load` unchanged and `tests/db/fixtures-load.test.ts` green as it stands (454 items, 5 editions, 5 edition sources, 37 contents)
- A2 Open Library client, `src/lib/providers/openlibrary.ts`: no key. `OPENLIBRARY_BASE_URL` (default `https://openlibrary.org`) and `OPENLIBRARY_COVERS_BASE_URL` (default `https://covers.openlibrary.org`) as optional server vars through `env.ts`'s pattern, the stub seams; `OPENLIBRARY_CONTACT` optional, so the `User-Agent` is `Fluxnook/<package.json version> (<contact, else https://github.com/WilliM233/fluxnook>)` on every call, as their policy asks. Calls: `GET /search.json?q=&fields=key,title,author_name,first_publish_year,cover_i,edition_count&limit=&page=` mapped to one plain shape (`key` = `works/OL…W`, `title`, `authors` deduped, `year` from `first_publish_year` or null, `editionCount`, `coverId`); `GET /works/<id>.json` for the description (string or `{value}`), covers and the first-publish date; `GET /isbn/<13>.json` followed through its redirect to the edition (`key` = `books/OL…M`, `title`, `publishers[0]`, `publish_date` parsed to a date and precision or year only, `number_of_pages`, `physical_format` mapped to `paperback` / `hardcover` / `ebook` / `audiobook` or null, `isbn_13` / `isbn_10`, `covers`, `works[0]`), then the work. Recorded responses for "carrie", "night shift", the Carrie and Night Shift and It works, and the two editions `9780307743664` and `9781501142970` live under `tests/fixtures/openlibrary/`, and the mapping is unit-tested against them. A non-2xx is a typed `ProviderError` carrying the status only; Open Library's own words never reach a response. Every call has a 10 s timeout
- A3 The ISBN. `src/lib/isbn.ts`: `normalizeIsbn(text)` strips hyphens and spaces, takes 10 digits (trailing X allowed) or 13, checks the digit, converts a 10 to its 13, returns the 13 or null. Unit-tested with `978-0-307-74366-4` → `9780307743664`, `0307743667` → the same, `978-0-307-74366-5` → null (bad digit), `9799999999994` → null, `0-8044-2957-X` → `9780804429573`. The browser and the route both use it; a request to Open Library is never made for text that doesn't normalize
- A4 `GET /api/v1/providers/openlibrary/search?q=&page=` (signed in; 401 otherwise; `q` under 2 characters is 400 `invalid_request`): Open Library results as A2's shape, each with `catalog`: `{ status: "in", itemId }` when `item_sources (openlibrary, <key>)` exists; `{ status: "match", itemId, title, year, author, source, shelf, candidates }` when no `openlibrary` source exists but a `book` item has the same normalized title and its `item_books.author`, folded by the same normalizer, equals any of the result's folded author names (the 2026-10-28 call: no year window for books); `{ status: "new" }` otherwise. One query for the keys, one for the candidates, per page. `catalogStatuses` in `src/lib/catalog/match.ts` takes the rule per type rather than growing a copy
- A5 `GET /api/v1/providers/openlibrary/isbn/<isbn>` (signed in): 400 `invalid_request` when A3 returns null; 404 `not_found` when Open Library has no edition (its 404); otherwise `{ edition: <A2's edition shape>, work: <A2's work shape with catalog as A4 computes it>, editionCatalog: { status: "in", editionId, itemId } | { status: "new" } }` where the edition is "in" when `edition_sources (openlibrary, books/OL…M)` or `(isbn, <13>)` exists
- A6 `POST /api/v1/items/import` takes `source: "openlibrary"` beside `tmdb` (Zod union, `key` matching `^works/OL[0-9]+W$` for Open Library), with the same `attachTo` and the same idempotent-by-key answer (201 new, 200 known). New book: `type` `book`, `form` `novel`, `title`, `released_on`/precision from the work's first-publish date when it parses (year at least), `summary` from the description, `created_by` null, `item_books.author` = A2's names joined with ", ", `item_sources (openlibrary, works/…, https://openlibrary.org/works/…)`. Attach: the rule is A4's for books (same type `book`, folded title, folded author in the result's names), 409 `conflict` otherwise or when the item already has an `openlibrary` source; fills `summary` only when null, never touches `form`, `author` or `title`, and takes the Q2 date rule from 1.2 (a finer date in the same year replaces a coarser one, a different year never replaces a held one). Then the cover: `-L.jpg` of the work's first cover id (`?default=false`, so a missing cover is a 404 not a pixel) written to `covers/openlibrary/<cover id>.jpg` with the server's Storage client and `cover_path` set when null; a cover failure logs and the import succeeds. 404 `not_found` when Open Library has no such work
- A7 `POST /api/v1/editions/import` `{ source: "openlibrary", key: "books/OL…M", format, attachTo?: uuid }` (signed in; `format` one of `paperback`, `hardcover`, `ebook`, `audiobook`; `attachTo` is the work's attach target when A5 said the work looks like one you have): in one transaction, imports the work exactly as A6 would (idempotent; `attachTo` passes through), then creates the edition under that item with `format`, `title` when it differs from the work's, `released_on`/precision from `publish_date`, `publisher`, `pages`, and two source rows: `(openlibrary, books/OL…M, https://openlibrary.org/books/…)` and `(isbn, <13>)` for each ISBN-13 the edition carries (a 10 with no 13 converted). 201 `{ id, itemId }`; 200 `{ id, itemId }` when the edition key or any of its ISBNs is already a source (idempotent, nothing written). 409 `conflict` when the Open Library edition's work key isn't the imported item's (the edition belongs to another work). The edition's cover is not stored (Deferral)

## 1. Feasibility (Nookkeeper)

- **What exists** (`dev` at `2ac600f`, read on disk 2026-10-28). The provider pattern is complete and one-shaped: `src/lib/providers/tmdb.ts` (a `createTmdb({apiKey, baseUrl, imageBaseUrl, fetch})` closure, typed `ProviderNotConfigured` and `ProviderError(status)`, `parseTmdbKey`, `safePosterPath`, `tmdbFromEnv()`), `src/lib/catalog/import.ts` (`importFromTmdb(db, tmdb, covers, {key, attachTo})`: canonical key, idempotent lookup, details, one transaction with `create` / `attach` / `writeChild` / `addFranchise`, then `cachePoster` with a 10 s timeout and a 5 MB cap), `src/lib/catalog/match.ts` (`catalogStatuses` with the film/tv rule inlined at lines 60–66 and the type map at line 24), `src/lib/catalog/normalize.ts`, `src/lib/covers.ts` (`CoverStore.put(path, bytes, type)`), `src/app/api/v1/providers/tmdb/search/route.ts`, `src/app/api/v1/items/import/{route,schema}.ts` (`source: z.literal("tmdb")`, `key` regex for TMDB keys only), `src/lib/env.ts` lines 41–44 and 51–56 (the optional server vars and `ServerEnv`). - **Schema today** (`src/db/schema.ts`). `editions` (line 233): `id`, `item`, `format` not null in the shared vocabulary, `title` null, `released_on` + precision, timestamps; no publisher, no pages. `edition_sources` (line 259): `(source, key)` primary key, `url` null, `edition` cascade. `item_books` (line 135): `author` text not null. `items_form_per_type` requires a book's `form` not null, so A6 must set one; `novel` is the call. The ISBN as an `edition_sources` row needs no schema; the primary key on `(source, key)` is what makes an ISBN unique across the catalog, which is the property the collection chapter will want. `tests/unit/schema.test.ts` expects timestamps on every table but `profiles`; two nullable columns on `editions` don't disturb it. `tests/db/fixtures-load.test.ts` counts `editions` and `edition_sources` against the files and the loader writes neither new column, so it stays green.
- **Open Library** (checked live 2026-10-28 with a `Fluxnook dev (…)` User-Agent). `GET /search.json` with `fields=key,title,author_name,author_key,first_publish_year,cover_i,edition_count` returns `docs[]` with `key` as `/works/OL81626W`, `author_name` as an array that can repeat a name (`'Salem's Lot` lists Stephen King twice) and `first_publish_year` that is wrong often enough to matter: Carrie 1974 (right), Night Shift **1960**, `'Salem's Lot` **1959**. That is why books match on author, never year, and why the row shows both years. The title can carry typographic quotes (`'Salem’s Lot`), which the normalizer already folds to `salems lot`. `GET /works/<id>.json`: `title`, `authors[].author.key`, `first_publish_date` as free text ("1974", "December 2002"), `covers[]` (may contain `-1`), `description` as a string or `{type, value}`. `GET /isbn/<n>.json` 302s to `/books/OL…M.json` (the client follows only to its own base host); the edition has `works[0].key`, `publishers[]`, `publish_date` free text ("2011", "May 1, 1990"), `number_of_pages`, `physical_format` (null on three of four King editions tried; "mass market paperback", "Library Binding" when set), `covers[]`, `isbn_10[]`, `isbn_13[]`. The ISBN lookup is loose: `9780000000002` and `9781234567897` both resolve to junk editions, so A3's check digit is the only thing between a typo and a wrong book; a valid-but-absent ISBN (`9799999999990`) is a plain 404. Authors need one more call each (`/authors/OL19981A.json` → `name`), but the search already carries `author_name`, so the work import takes the names from the search row when it has them and falls back to the author calls when it came through an ISBN (the edition carries author keys only). Covers: `https://covers.openlibrary.org/b/id/<id>-L.jpg` 302s to the archive; with `?default=false` a missing id is a 404, without it a 1×1 pixel. Rate limit 1 req/s anonymous, 3 req/s identified by User-Agent; the ISBN path makes three calls (edition, work, authors) and the search one plus one per row for descriptions if we fetch them, which we don't: a row's second line is the author, not a summary, by design, so search is one call. No attribution is required; the footer line is manners.
