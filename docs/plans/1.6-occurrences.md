## 0. Spec (Nookkeeper)

**What this chapter delivers.** The journal arrives. On a work's page you log a read or a watch: where it stands (reading, done, abandoned), the dates if you have them, stars in half steps, and a first entry if you have something to say. Entries pile up under the read they belong to, each dated and, when you say where, pinned to a page, a chapter, an episode or an issue. The work's page shows every read with its entries; a Journal page shows every entry across every work, newest first. A shelf shows the stars its works have earned and, when you mark a work done on it, offers to log the read. The 26 Mirage reads the fixture already carries show up on their issue pages on the first load. One migration (the one-open-read rule), no provider.

**Acceptance.**
- A1 Schema. `occurrences` (`owner`, `item`, `status` in `in_progress`/`done`/`abandoned`, `started_on`, `finished_on`, `stars` numeric(2,1) in half steps 0.5–5.0 or null, `visibility`) and `journal_entries` (`occurrence`, `written_at`, `body`, `anchor_kind` in `page`/`chapter`/`episode`/`issue` with `anchor_value` both or neither, `visibility`, cascade from the occurrence) carry everything this chapter writes (`src/db/schema.ts` 474–535, Ch 1.1). One migration, through Drizzle as the `migrations` skill says: a partial unique index `occurrences_one_open` on `(owner, item) where status = 'in_progress'`, the rule behind A3's 409; reversible by dropping it. `db:check` clean; `fixtures:load` unchanged (it writes the 26 `done` occurrences today, `src/fixtures/load.ts` 385); `journal_entries` has zero rows after a load. If the census finds a column missing, it is a section 0 correction, not a quiet migration
- A2 Words. One function, `src/lib/journal/words.ts`, unit-tested, says the verb per type: a **read** for a book or a comic, a **watch** for a film or a show (a play waits for games). It gives every label this chapter prints: "Log a read" / "Log a watch", the status words Reading / Watching, Done, Abandoned, "1 read" / "2 reads" / "watched 3 times", and which anchor kinds the type takes: book `page`, `chapter`; comic issue `page`; comic collected `issue`, `page`; TV `episode`; film none (no "Where in it" row). The anchor pill prints `page` as "p. 112", `chapter` as "Ch. 7", `episode` as the value typed ("S02E03"), `issue` as "#7"; one formatter, unit-tested
- A3 Reads, `src/app/api/v1/occurrences`: `POST` `{ item: uuid, status, startedOn?: "YYYY-MM-DD", finishedOn?: "YYYY-MM-DD", stars?: number, entry?: { body, anchorKind?, anchorValue? } }` → 201 `{ id, entryId? }`, the read and its first entry in one transaction, owner the signed-in user, visibility `private`, no control shown (Volume 2). Rules, each a 400 with a field error: `stars` is null or 0.5 to 5.0 in half steps; `finishedOn` is not before `startedOn` when both are set; a Reading read has no `finishedOn`; `item` must be a catalog item (404 when not). A second Reading on the same work is 409 `conflict`, "You're already reading this. Finish or abandon that read first." (A1's index is what makes it true under a race). `PATCH /<id>` `{ status?, startedOn?, finishedOn?, stars? }` → 200 with the read as it now stands, the same rules, `{}` 400 "Nothing to change."; `DELETE /<id>` → 204 and its entries go with it (the schema's cascade). Every route: 401 signed out; 415 off JSON; 404 `not_found` for a read that isn't the caller's, never 403
- A4 Entries, `src/app/api/v1/occurrences/<id>/entries`: `POST` `{ body, anchorKind?, anchorValue?, writtenAt?: ISO timestamp }` → 201 `{ id }`; `body` trimmed, 1 to 20,000 characters, line breaks kept; the anchor both or neither (the schema's check, answered as a 400 before it); `anchorKind` must be one A2 allows for the work's type (400 naming the kinds it takes); `writtenAt` defaults to now and may be set (a journal catches up; a date in the future is 400). `PATCH /<eid>` `{ body?, anchorKind?, anchorValue?, writtenAt? }` → 200; `DELETE /<eid>` → 204. 404 for an entry not on the caller's read
