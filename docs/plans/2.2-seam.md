**Acceptance.**
- A1 One set of handlers, two doors. Every `api/v1` route the pages call (the 25 today less the three `auth` routes, plus A3's reads) has its body in a handler that takes the database, the caller's id and the request and returns a `Response`; the handlers live in one place the census names. Each `route.ts` is a wrapper: the caller from the session (`callerId`), else `signInFirst()`, then the handler. Paths, methods, statuses, bodies and headers unchanged; every existing unit, db and e2e suite green unchanged. `Db` (`src/db/client.ts`) becomes Drizzle's Postgres database type over the schema, so every `src/lib` service takes the hosted `postgres` driver and PGlite alike; `npm run typecheck` is the witness
- A2 The transport. One function, `nookFetch(path, init)`, is the only way client code reaches `api/v1`: hosted it is `fetch`; on the device it matches the path against one table of A1's handlers and calls the handler in-process on the device's PGlite as the device's one person (`DEVICE_USER_ID`), answering a real `Response`, so every view's status handling (the 404s, the 409 on a stale version, the refusals' words) runs unchanged. A path the table doesn't hold answers 404 in words. Witnesses: a unit test that fails on a raw `fetch("/api/v1` or `` fetch(`/api/v1 `` in client code outside the transport; a Vitest that sends the same requests through both doors (hosted against the test database, device against PGlite in Node) and compares status and body for at least: add a shelf, add works to it, move one, log a read with stars, add a journal entry, own a copy, untick an owned issue
- A3 Reads. Each page's loader (the nook, a shelf and its picker list, an item, a series, the journal, the collection, shopping; names at the census) is served by a GET under `api/v1` through A1's handlers, owner-checked exactly as the loader is today. ## 1. Feasibility (Nookkeeper)

Read on disk 2026-11-08 at `dev` `f63f6b2` (`git status -sb` level with `origin/dev`). Each count names its command, run from the repo root; a claim no file or run settled is marked unverified.

- **The routes are already thin.** `find src/app/api/v1 -name route.ts | wc -l` is 25; 8 export a GET (`grep -rl 'export async function GET' src/app/api/v1 | wc -l`), and 4 of those are providers', 2 are auth or me. A route reads the caller (`callerId`), the path ids (`pathIds`), the body through its Zod schema (`readBody`), calls one `src/lib` function with `serverDb()` and maps a thrown refusal (`refusal`); `src/app/api/v1/shelves/[id]/entries/route.ts` is the shape, 40 lines. So A1 is a move, not a rewrite: the helpers in `src/app/api/v1/respond.ts` and `src/lib/api/` go to the handlers' side, and only `callerId` and `serverDb()` stay in the wrapper
- **The database type.** `src/db/client.ts` types `Db` as `ReturnType<typeof createDb>["db"]`, the `postgres-js` database; `grep -rho 'db: Db' src/lib | wc -l` is 51 in 25 files (`grep -rl … | wc -l`), and `grep -rl 'from "@/db' src/lib | wc -l` is 30. The device's `DeviceDb` (`device/db.ts`) is `PgliteDatabase<typeof schema>`. Both extend Drizzle's `PgDatabase`; a shared type over the schema should take both (unverified: transactions and `execute`'s row shape differ by driver, `{ rows }` on PGlite, an array on `postgres-js`; `device/shelves.ts` reads `rows[0]`, so any service calling `execute` is a census line)
- **The pages.** `find src/app -name page.tsx | wc -l` is 10: the sign-in page at `/` and nine under `(app)` (collection, shopping, items/new, items/[id], journal, nook, search, series/[id], shelves/[id]). Each server page reads the user from Supabase and calls a loader (`loadShelfPage(db, { id, userId })`, `src/app/(app)/shelves/[id]/page.tsx`) then hands the result to a client view; `src/app/(app)/layout.tsx` guards and passes `user.email` to the header. `grep -rl 'router.refresh()' src | wc -l` is 13
- **The client calls.** `grep -rn 'fetch(' src --include=*.ts --include=*.tsx | grep -v 'src/lib/providers\|src/app/api' | wc -l` is 38, in 19 files (the same with `-l`). `grep -rlE "^['\"]use client['\"]" src | wc -l` is 34 client files, with 20 imports from `next/link` or `next/navigation` among them (the loop over those files, `grep -hE 'from "next/'`)
- **What's hosted-only under `src/lib`.** `src/lib/supabase/` (Next headers and the Supabase client); `src/lib/env.ts`, read by `covers.ts` and the three provider clients (`process.env`, which a Vite build doesn't have; unverified whether `define` covers it, and A7 keeps those off the device's table anyway); `covers.ts`, imported by `catalog/editions.ts`, `import.ts` and `series.ts`, the provider import paths. So the device table holds no provider route and no import route, and the census checks no device module reaches `covers.ts` or `env.ts` through an import chain (a bundle that pulls in the Supabase storage client is the sign)
- **The device side today.** `device/` is a Vite 8.3.4 entry with `@tailwindcss/vite` 4.3.3 (`package.json`), `db.ts` (the store, the stand-ins, the migrator, `holdTheStore`, the damaged-store refusal), `shelves.ts` (a duplicate of the shelf add with its own flush rollback, A5 folds it), `stub-page.tsx` (182 lines, `grep -c ''`). Manual entry (`src/app/(app)/items/new`) calls `/api/v1/items` and no cover code (`grep -n 'cover\|upload'` on its files prints nothing)
- **Why Vite, not a static export.** `next.config.ts` sets no `output`; a static export can't serve route handlers and needs every `[id]` page's params known at build (unverified, from Next's docs as remembered; the census reads Next 16.4.2's). The Vite entry already builds in `build.yml` and passes the CSP. Its cost is A4's adapter and a route table, which A2 already needs
- **Risk, medium-high.** The size: 9 pages, 19 files of calls, 25 routes moved, all of it witnessed by the existing suites, which is why each Signature must leave hosted green. The second risk is drift between the doors (a header or a status the device answers differently); A2's parity test is its witness. The third is the phone: the real app's bundle and first open on Android System WebView are unmeasured (2.1 measured the stub), and A8's words are what a slow phone shows. Likely cut: three, as Run says, the device app last with the exit Browse
