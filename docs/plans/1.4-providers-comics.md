## 0. Spec (Nookkeeper)

**What this chapter delivers.** The third provider, and the one the TMNT sheet was waiting for. Signed in, you search Comic Vine for a comic series from the same box that searches TMDB and Open Library, see which series are already in your catalog or look like a run you entered by hand, and add one: the series and every issue Comic Vine lists for it come in together, covers included. A series has a page of its own now, the run in cover-date order, and an issue's page says where it sits in the run and which collected editions hold it. A run of trades imports as collected editions, and what each one collects is picked by hand from the catalog, since no provider carries that as data. The 366 Mirage comics in the fixture, which have no provider yet, get their Comic Vine details attached rather than duplicated. One key, from one Comic Vine account, on the server.

**Acceptance.**
- A1 Schema. One generated migration, appended (the 1.3 migration has reached `dev`), reversible: a `series` catalog table (`id`, `name` not null, `volume integer null`, `year_began integer null`, `year_ended integer null`, `publisher text null`, `kind text null` in `seriesKinds`, `summary text null`, `cover_path text null`, timestamps) with `series_sources (source, key)` primary key, `url null`, `series` cascade, shaped as `franchise_sources`; `item_comics.series_id uuid null` referencing `series` (restrict on delete, as the catalog does), the `series` text column kept. No creators column: the probe showed credits come only from the per-issue detail call (Deferral). `db:check` clean; `fixtures:load` unchanged and `tests/db/fixtures-load.test.ts` green as it stands (454 items, 366 `item_comics`, 5 editions, 5 edition sources, 37 contents)
- A2 Comic Vine client, `src/lib/providers/comicvine.ts`, a sibling of the TMDB and Open Library clients: `COMICVINE_API_KEY` optional server var (empty means `ProviderNotConfigured`, the route's 503 "Comic search isn't set up on this nook yet"), `COMICVINE_BASE_URL` (default `https://comicvine.gamespot.com/api`) the stub seam, `COMICVINE_CONTACT` optional for the `User-Agent` `Fluxnook/<package.json version> (<contact, else the repo URL>)`, which Comic Vine requires to be set to something. The key rides every call as `api_key=` in the query string, by their design; the client never logs, throws or returns a URL that holds it, and a `ProviderError` carries the status and Comic Vine's `status_code` only. Calls, each with `format=json` and a `field_list`: `GET /search/?resources=volume&query=&limit=20` mapped to one series shape (`key` = `volume/<id>`, `name`, `year` from `start_year` or null, `publisher` name or null, `issueCount` from `count_of_issues`, `coverUrl` from `image`, `url` from `site_detail_url`, `summary` from `deck`); `GET /volume/4050-<id>/` for the same plus `description`; `GET /issues/?filter=volume:<id>&sort=cover_date:asc&limit=100&offset=` paged by `number_of_total_results`, each issue mapped to (`key` = `issue/<id>`, `number` as Comic Vine's string, `name` or null, `coverDate` parsed to a date or null, `coverUrl` from `image.original_url`, `url`, `summary` from `description` cut to its first paragraph with the tags stripped and entities decoded, the 1.3 blurb rule's shape); the list resource serves `description` and not `person_credits` (probe, 2026-10-29), so no detail call is made this chapter. Recorded responses for the search "teenage mutant ninja turtles", the 1984 Mirage volume (`volume/20281`) and its issue list, the Ultimate Collection volume (`volume/50804`) and its issue list, the Tales 1987 volume (`volume/18790`), and "Tales of the TMNT" (`volume/18785`, the fixture's Tales Vol. 2 under Comic Vine's name) live under `tests/fixtures/comicvine/`, recorded by the Binder with `scripts/comicvine-record.ts`, and the mapping is unit-tested against them. Every call has a 20 s timeout. Comic Vine's velocity error (its `status_code` for too many requests) is a typed `ProviderBusy` the routes turn into 503 "Comic Vine is busy. Try again in a few minutes."; the client makes no retry
- A3 Keys. `parseComicVineKey` accepts `volume/<int>` and `issue/<int>` and rebuilds the `4050-`/`4000-` form for the call; a key with the prefix typed in is 400. The `comicvine` source URL on an item or series is Comic Vine's `site_detail_url`, the link their attribution rule wants on every page that shows their data
- A4 `GET /api/v1/providers/comicvine/search?q=` (signed in; 401 otherwise; `q` under 2 characters is 400): series rows as A2's shape, each with `catalog`: `{ status: "in", seriesId }` when `series_sources (comicvine, volume/<id>)` exists; `{ status: "match", label, count, earliest, shelf, candidates }` when no such source exists and a group of `comic` items with no `comicvine` source shares an `item_comics.series` text whose fold, after a trailing `Vol. <n>` and a `(…)` publisher are stripped, equals the folded volume name, and whose earliest `released_on` year is within 1 of `start_year` (2026-10-29 call; a group with no year at all never matches); `{ status: "new" }` otherwise. `catalogStatuses` takes the rule as a third comparator beside film/tv and book, not a copy
- A5 `POST /api/v1/series/import` `{ source: "comicvine", key: "volume/<id>", form: "issue" | "collected", format?: "tpb" | "hardcover" | "omnibus", attachTo?: string }` (signed in; `format` required when `form` is `collected`; `attachTo` is a hand-entered group's series text: A4's `label` when the status was match, or any group the person picked on the sheet when it wasn't, since Comic Vine names the fixture's Vol. 4 "TMNT:  Teenage Mutant Ninja Turtles" and its Tales Vol. 2 "Tales of the TMNT", which no fold reaches): in one transaction per page of issues, creates the `series` row (`name`, `volume` parsed from a trailing "Vol. n" of the attached label when there is one, `year_began`, `year_ended` from the last issue's cover date when the volume's `count_of_issues` equals the issues fetched and the last cover date is before this year, `publisher`, `kind` null, `summary` from `deck`, `series_sources (comicvine, volume/<id>, url)`), then every issue: with `form` `issue`, a `comic` item of form `issue` (`one-shot` when the volume has one issue), `title` = Comic Vine's name or "<series name> #<number>" (8 of the Mirage 62 have no name), `summary` from A2's blurb, `released_on` = cover date at `month` precision (Comic Vine's cover dates are the last day of the month, "1984-05-31", so the day is noise), `item_comics` (`series` text = the attached label or the volume name, `series_id`, `number` when the string is an integer), `item_sources (comicvine, issue/<id>, url)`; with `form` `collected`, a `comic` item of form `collected` with one `editions` row of `format`, `released_on` the cover date, `publisher`, `edition_sources (comicvine, issue/<id>, url)` and no contents. Attach, when `attachTo` names a group: an issue attaches to the group's item with the same `number` (form `issue`); a collected volume attaches to a held `collected` comic with no `comicvine` source whose title ends in the same number and whose folded title, number removed, is a substring of the folded volume name; an attach adds the source row, sets `series_id`, fills `summary` only when null, takes the 1.2 date rule, keeps the held title, form and series text, and for collected adds the edition under the held item when it has none of that format. Idempotent: 200 `{ id }` with nothing written when the volume's source row exists; 201 `{ id, created, attached }` otherwise. 409 `conflict` when `attachTo` names no group, or a group whose items already carry a `comicvine` source (it was attached to another volume). A 150-issue volume is two `issues` calls
