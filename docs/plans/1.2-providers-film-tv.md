## 0. Spec (Nookkeeper)

**What this chapter delivers.** The first screens, and the first provider. Signed in, you search TMDB for a film or a show, see at a glance which results are already in the catalog and which look like something you already have, and add one with a click; the poster comes with it. Each item in the catalog has a page: cover, facts, where it came from, what it's connected to, which of your shelves it sits on. For the things no provider knows, a plain form adds an item by hand. The nook gets its look: Deep Field, the galaxy palette, Fraunces and Inter. Shelves, reads and copies still have no screens; this chapter builds the page they'll land on.

**Acceptance.**
- A1 Look and shell. `globals.css` defines the Deep Field tokens as CSS variables on `:root` (ground `#0E0B17`, surface `#171226`, line `#2E2544`, strong line `#3C3158`, text `#F0ECF8`, muted `#A79BC2`, dim `#8578A3`, accent `#C9A2F5`, accent hover `#DDBFFA`, accent ink `#17102A`) and maps shadcn's `--background`, `--card`, `--border`, `--foreground`, `--muted-foreground`, `--primary`, `--primary-foreground` onto them, so the three `ui/` components take the look without edits. Fraunces (titles) and Inter (text) through `next/font`, replacing Geist. A signed-in app shell under a route group, `src/app/(app)/layout.tsx`: header with the wordmark, Search and Nook links, the email, Sign out; footer with the TMDB attribution line and logo ("This product uses the TMDB API but is not endorsed or certified by TMDB", a TMDB term). `/nook` moves into the group and keeps its words; `/` (sign-in) stays outside. Unsigned requests to any page in the group redirect to `/`, as `/nook` does today
- A2 Schema. One generated migration: `items.type` check gains `tv`; `items_form_per_type` gains `(type = 'tv' and form is null)`; `items` gains `summary text null` and `cover_path text null`; new `item_films (item pk → items cascade, runtime_minutes int null, original_title text null)` and `item_tv (item pk, seasons int null, episodes int null, original_title text null, first_aired date null, last_aired date null, ended boolean not null default false)`, both with `created_at`/`updated_at` and an `updated_at` trigger in the same `--custom` pattern as 1.1. One `--custom` migration creates the Storage bucket: `insert into storage.buckets (id, name, public) values ('covers', 'covers', true)`, Down deletes it (objects first). Appended, not folded: the 1.1 migrations have reached `dev`. `db:check` clean; `fixtures:load` unchanged and the 1.1 counts still hold (`tests/db/fixtures-load.test.ts` green as it stands)
- A3 TMDB client, `src/lib/providers/tmdb.ts`: `TMDB_API_KEY` (the v4 read token, server-only, never `NEXT_PUBLIC_`) read through `env.ts`'s pattern as an optional server var; `TMDB_BASE_URL` optional, default `https://api.themoviedb.org/3`, so tests can point it at a stub. Calls: multi search filtered to `movie` and `tv`, movie details, TV details, each mapped to one plain shape (`kind`, `key` = `movie/<id>` or `tv/<id>`, `title`, `year`, `releasedOn` + precision, `summary`, `posterPath`, `originalTitle`, `runtimeMinutes`, `seasons`, `episodes`, `firstAired`, `lastAired`, `ended`, `collection` {key, name} or null). Recorded responses for "carrie" (search), one movie and one show live under `tests/fixtures/tmdb/`, and the mapping is unit-tested against them. With no key, the client throws a typed `ProviderNotConfigured`; the search route turns it into 503 `provider_unavailable`; nothing else breaks
- A4 `GET /api/v1/providers/tmdb/search?q=&type=all|film|tv&page=` (signed in; 401 otherwise): TMDB results as A3's shape, each with `catalog`: `{ status: "in", itemId }` when `item_sources (tmdb, <key>)` exists; `{ status: "match", itemId, title, year, source, shelf }` when no `tmdb` source exists but one item of the same type (tv ↔ `tv`, movie ↔ `film`) has the same normalized title (case, punctuation and leading article folded) and a year within 1; `{ status: "new" }` otherwise. One query for the keys, one for the candidates, per page. `q` under 2 characters is 400 `invalid_request`
- A5 `POST /api/v1/items/import` `{ source: "tmdb", key, attachTo?: uuid }` (signed in): fetches details, then in one transaction either creates the item (`type` from the kind, `released_on`/precision from the date, `summary`, `original_title` and the type's columns, `created_by` null, `item_sources (tmdb, key, url)` with the TMDB page URL) or, with `attachTo`, adds the `tmdb` source and fills every null column on that item and its child row (never overwriting a non-null `title`, `released_on` or `summary`; `item_films`/`item_tv` created if missing). Then the poster: w500 fetched server-side and written to `covers/tmdb/<kind>/<id>.jpg` with the server's Storage client; `cover_path` set; a poster failure logs and leaves `cover_path` null, the import still succeeds. Collection → `franchises` + `franchise_sources (tmdb, collection/<id>)` + `item_franchises`, upsert on the source. 201 `{ id }` for a new item, 200 `{ id }` when the key already has an item (idempotent; `attachTo` ignored then). 409 `conflict` when `attachTo` already has a `tmdb` source or is another type; 404 `not_found` when TMDB has no such key
- A6 `POST /api/v1/items` (manual, signed in): `{ type, title, year?, month?, day?, summary?, form?, author?, series?, seriesKind?, number?, runtimeMinutes?, seasons?, episodes? }`, Zod-validated per type (a book needs `form` and `author`; a comic `form`; film and tv forbid `form`; month without year and day without month are 400). Creates the item with `created_by` = the user and `item_sources (manual, <item uuid>)`. 201 `{ id }`
- A7 `/search`: the search screen. Input, All/Films/TV, results as the design's rows with the three states: in → "Open" to the item; match → "Add" opens the match sheet (TMDB side, catalog side with its source and shelf, "Same, add the TMDB details to it" → import with `attachTo`, "Different, add as new" → plain import, Cancel); new → "Add" imports and goes to the item page. Debounced 300 ms, URL carries `q` and `type` so a search can be shared or refreshed. Empty query lists the catalog's 12 most recently created items as the same rows with "Open". 503 from the route shows "Search isn't set up on this nook yet" in place of results, nothing else
- A8 `/items/<uuid>`: the item page as designed, server-rendered. Cover from `cover_path` (public bucket URL) or the dashed "no poster" box; type pill, year, the type's facts (film: runtime; tv: seasons, episodes, Ended or Returning, first and last aired; book: form, author; comic: series, kind, number); title; summary or nothing; Released with the date at its precision (16 November 1976; May 1984; 1979); Original title when it differs; Franchise; Sources as outbound links by source (`tmdb` → the TMDB page, `letterboxd` → the URL on the row, `manual` → "Added by hand"); Connected: every relation in either direction, labelled by kind and direction ("Adaptation of", "Adapted as", "Contained in", "Contains"), each a link; On your shelves: the signed-in user's shelves holding the item, with the entry's position, or the one-line placeholder. Unknown uuid is 404 with the app shell. Readable at 390 px wide: the cover stacks above the facts
- A9 `/items/new`: the manual form as designed, fields changing with the type, Zod errors shown by field, success goes to the new item's page
- A10 Seen red, each once and reverted: `TMDB_API_KEY` unset → `/search` shows the 503 line and `/items/<uuid>` still renders; an import with `attachTo` pointing at an item that already has a `tmdb` source → 409 and no row changed; a second import of the same key → 200, `items` count unchanged; the poster URL made unreachable (`TMDB_BASE_URL` stub returning 500 for the image) → import 201 with `cover_path` null; a manual book without `author` → 400 naming the field
- A11 Tests. Unit: the TMDB mapping on the recordings, the title normalizer (with "The Rage: Carrie 2", "Carrie", "carrie!" cases), the manual schema. db (`test:db`, against the loaded fixtures): A4's three statuses for "carrie" (1976 in, 2013 match, The Carrie Diaries new) with the client on a stub; A5's new, attach and idempotent paths and the counts they leave (454 → 455 items after one new; 455 `item_sources` after one attach; `item_films` 1; `cover_path` set when the stub serves an image); A6. e2e: `/search` with the stub (`TMDB_BASE_URL` pointed at a Playwright-started fixture server serving the recordings and a 1×1 jpg), through the match sheet to the item page; `/items/new` end to end; `/items/<uuid>` for Carrie 1976 shows "Adaptation of · Carrie" and "Stephen King Watch List"; the unsigned redirect for all three pages. CI's stack gains `storage-api` (the `-x` list drops it) so the cover write is real in `test:db` and e2e
- A12 Docs. README: Screens section (the three pages and what they do), `TMDB_API_KEY` in Getting started with where to get one, the stub for tests; `docs/API.md`: the three routes with their errors and the "what someone would get wrong" lines (the key is server-only; import is idempotent by key; attach never overwrites); `docs/STACK.md`: any package added, and the storage service in the stack note; `.env.example` gains `TMDB_API_KEY=` (empty, commented: get one at themoviedb.org/settings/api) and `SUPABASE_SECRET_KEY` with the CLI's fixed local default, commented server-only; `docs/releases/1.2.md`; `package.json` `0.1.0-ch.2`

## 1. Feasibility (Nookkeeper)

- **What exists** (`dev` at `8c3a79c`, read on disk 2026-10-24). `src/app/`: `layout.tsx` (Geist via `next/font`, `font-sans`), `page.tsx` + `sign-in-form.tsx`, `nook/page.tsx` (server component, `createClient()` + `getUser()`, `redirect("/")` when unsigned, shadcn classes) and `nook/sign-out-button.tsx`; `api/v1/` with `me`, `auth/magic-link`, `auth/callback`, `auth/sign-out`, each route a plain handler using `apiError()` and `noStore` from `src/lib/api/errors.ts` and a sibling `schema.ts` where there's a body. `src/lib/env.ts` validates only the two `NEXT_PUBLIC_` vars with Zod and throws naming the missing one; `TMDB_API_KEY` and the Storage key join it as server-only optionals read the same way, never inlined. `src/lib/supabase/server.ts` builds the SSR client on the publishable key; `src/proxy.ts` refreshes the session on every non-asset path. `src/components/ui/`: `button`, `input`, `label` only (shadcn base-nova); `globals.css` is shadcn's token sheet in oklch with a `.dark` variant, light by default. No route group, no shared header, no footer, no `select` or `textarea` component, no `src/db/client.ts` consumer outside the loader and tests.
- **Schema today** (`src/db/schema.ts`, 1.1): `items.type` check is `film`/`book`/`comic`; `items_form_per_type` has no `tv` arm, so a `tv` row with null `form` fails today; no `summary`, no `cover_path`; `item_films` and `item_tv` absent. The alter is a generated migration (drizzle-kit emits `DROP CONSTRAINT` + `ADD CONSTRAINT` for a changed check, as `items_form_required` showed); its Down is the two old checks back and the four drops. `tests/unit/schema.test.ts` (1) expects `created_at`/`updated_at` on every table but `profiles`, so the two child tables carry them and get triggers in the `--custom` file; its catalog-table list (2) and `rummage-schema` R2's "a fourth `type`" case both name the current vocabulary and must change with it (R2 should try `game`, not `tv`).
- **Storage.** `config.toml` `[storage] enabled = true`, no buckets; the stack action's `-x` list excludes `storage-api` (and `imgproxy`, which only transforms serve, so it stays out). Bucket as a migration row in `storage.buckets` applies locally and hosted alike; `[storage.buckets.<name>]` in `config.toml` would be local-only. Writing an object needs a key with Storage rights: the publishable key as the user is subject to `storage.objects` RLS, which has no policies; the CLI's fixed local secret key (`npx supabase status` prints it, `sb_secret_…` on current CLIs, `service_role` JWT on older) used by a server-only Storage client is the plain route and parallels the TMDB token. It joins `.env.example` with the same "fixed local default, belongs to no hosted project" comment as the publishable key. Public read URL: `<SUPABASE_URL>/storage/v1/object/public/covers/<path>`; `next.config.ts` needs nothing for a plain `<img>`.
- **TMDB.** v4 read token as `Authorization: Bearer`; `GET /3/search/multi?query=&page=` returns `media_type` in `movie`/`tv`/`person` (filter the third); `GET /3/movie/{id}` has `runtime`, `release_date`, `original_title`, `overview`, `poster_path`, `belongs_to_collection {id, name}`; `GET /3/tv/{id}` has `first_air_date`, `last_air_date`, `number_of_seasons`, `number_of_episodes`, `status` (`Ended`, `Returning Series`, `Canceled`, …), `original_name`, `overview`, `poster_path`, no collection. Posters at `https://image.tmdb.org/t/p/w500<poster_path>`. Dates are full `YYYY-MM-DD` or empty, so precision is `day` or null; a result's `year` for A4's matching is the date's year. Rate limit is generous (tens of requests a second); the chapter adds no cache. Attribution: TMDB's terms require the "not endorsed or certified" line and their logo where the API is used; the logo SVG is downloaded into `public/` with its source noted. The Cartographer records the three fixtures with the real API (the token is on L's machine, not in CI) and commits the JSON with ids and poster paths intact; the recordings are the only TMDB data CI ever sees.
- **Matching.** Normalizer: lowercase, strip diacritics, drop everything but letters, digits and spaces, collapse spaces, drop a leading `the`/`a`/`an`. The 61 films are `letterboxd:` rows with `year` and title from the Letterboxd list; "The Rage: Carrie 2" normalizes to `rage carrie 2`, "Carrie" to `carrie`, so the 1976 and 2013 Carries are told apart by year only (both exist in the fixture; the 2002 TV film too, which TMDB lists as a movie). The 1-year window is for Letterboxd's premiere-vs-release years; the Browse's three Carries sit two or more years apart from each other. A match that finds two candidates returns both in `catalog.candidates` and the sheet lists them; the design shows one.
- **The stub.** `TMDB_BASE_URL` is the seam: unit tests inject `fetch`; `test:db` and e2e start a small Node server (Playwright `webServer` can start two) serving `tests/fixtures/tmdb/` by path and a 1×1 jpg under `/t/p/w500/`, and set `TMDB_BASE_URL` and the image base to it (one more optional var, `TMDB_IMAGE_BASE_URL`, default `https://image.tmdb.org/t/p`, so the stub covers both). With `TMDB_API_KEY` set to any non-empty value in the test env and the stub ignoring it, CI needs no secret. SSRF note for the Raccoon: the route must never take a base URL or a poster URL from the request; the only URLs built are from env plus TMDB's returned `poster_path`, which is validated to `^/[A-Za-z0-9]+\.(jpg|png)$` before use.
- **The route group.** `(app)/layout.tsx` does the `getUser()` + `redirect("/")` once; `nook/page.tsx` moves under it and drops its own check. `tests/e2e/guards.spec.ts` names `/nook` today and gains the two new pages. The sign-in page keeps its own layout. The footer attribution is in the group layout, so every signed-in page carries it.
- **Fonts and tokens.** `next/font/google` with `Fraunces` (`variable: "--font-heading"`, axes `opsz`, weights 400/600) and `Inter` (`--font-sans`); `globals.css` already declares `--font-heading: var(--font-sans)`, so the heading variable gets its own font. Deep Field goes into `:root` in oklch or hex (hex is what the design states; oklch conversions are the Cartographer's if the sheet stays oklch). Light mode is not drawn and `.dark` becomes unused; left in place for the theme Deferral.
- **Loader and fixtures untouched.** `fixtures:load` writes no `summary`, `cover_path`, `item_films` or `item_tv`; new nullable columns and new tables don't change its counts. A6's manual items are distinguishable from loader `manual:` rows by `created_by` being set.
- **Volume 0 and 1.1 carry-ins.** None queued. House Rules step 0 (design before spec) is met by the header link; this is its first use.
- **Risk, moderate.** Three new surfaces (shell, three routes, three pages) is the widest chapter so far by file count, but each piece is shallow and the data model under it is settled. The two places it can go wrong: the stub (if `TMDB_BASE_URL` isn't a clean seam, e2e gets flaky or skipped) and Storage in CI (a service that hasn't run in the runner yet). Both are step 1 work by design, so they fail early. The secret key is the one thing in this chapter that can hurt if mishandled; it lives server-side only and the Raccoon's first look is at the bundle.
