## 0. Spec (Nookkeeper)

**What this chapter delivers.** The nook stops being empty. Signed in, you see your shelves, make one, and put works on it from three places: the work's own page, the shelf itself (a picker over your catalog), and a comic series' page, which puts the whole run on in one go. A shelf has sections, one level deep; you drag works into order and between sections, or move them with the keyboard. Each work on a shelf carries the shelf's own status, unmarked, done or skipped, and a skipped work stays visible. The three fixture shelves (the King watch list, the King works in publication order, the Mirage run in its fourteen sections) are the first thing the nook shows, and the King path, book then films, section per work, is built by hand on the Browse. No migration, no provider, no occurrence: the shelf's status is the shelf's, and the journal arrives in Ch 1.6.

**Acceptance.**
- A1 Schema. No migration: `shelves` (`owner`, `name`, `description` default `''`, `source_url`, `visibility`), `shelf_sections` (`shelf`, `name` unique per shelf, `position`) and `shelf_entries` (`shelf`, `section` null, `item` unique per shelf, `position`, `status` in `unmarked`/`done`/`skipped`, `visibility`) carry everything this chapter writes (`src/db/schema.ts` 400–470, Ch 1.1). `db:check` clean; `fixtures:load` unchanged and `tests/db/fixtures-load.test.ts` green as it stands. If the census finds a column missing, it is a section 0 correction, not a quiet migration
- A2 Order, the one rule every write keeps. A shelf's entries are ordered by `position`, integers 1..n across the whole shelf, renumbered by the server on every write that moves anything (Roadmap 2026-10-23: integers renumbered on move; lexorank only if drag earns it). The display order, and so the numbering, is: entries with no section, by position; then each section by its `position`, its entries by theirs. A move is "this entry goes into this section (or none) at this index", and the server rewrites every position on the shelf in one transaction, so the shelf never holds two of a position or a gap. The renumbering is one function, `src/lib/shelves/order.ts`, pure over a list, unit-tested on its own, and the only place positions are computed
- A3 Shelves, `src/app/api/v1/shelves`: `POST` `{ name, description? }` (name trimmed, 1 to 120 characters; description up to 2000, default empty) → 201 `{ id }`, owner the signed-in user, visibility `private`, no control shown (Volume 2); `PATCH /<id>` `{ name?, description? }` → 200; `DELETE /<id>` → 204, the schema's cascade taking sections and entries, the catalog untouched. Every shelf route: 401 signed out; 404 `not_found` for a uuid that isn't the caller's shelf, never 403, so another person's shelf id tells nothing; 400 with field errors from Zod. `GET` reads are server components, not routes (as the item page), except what the sheets need: `GET /api/v1/shelves` → the caller's shelves as `{ id, name, count, sections: [{ id, name }], has: boolean }` with `?item=<uuid>` filling `has` (A9, A11)
- A4 Sections, `src/app/api/v1/shelves/<id>/sections`: `POST` `{ name }` (1 to 120, unique on the shelf; a duplicate is 409 `conflict` naming the section) → 201 `{ id }` appended last; `PATCH /<sid>` `{ name?, position? }` → 200, a position move renumbering the sections and then the entries (A2); `DELETE /<sid>` → 204 and, in the same transaction, its entries become unsectioned, placed after the shelf's unsectioned entries in their own order, then the whole shelf renumbered (2026-10-30 call: a section delete never drops a work). 404 for a section not on the caller's shelf
- A5 Entries, `src/app/api/v1/shelves/<id>/entries`: `POST` `{ items: uuid[], section?: uuid }` → 201 `{ added: n, skipped: n }`: the items go on the shelf in the order given, after the last entry of the section (or of the unsectioned part), status `unmarked`, visibility `private`; an item already on the shelf is counted in `skipped` and left where it is, not an error (so the run from A11 can be added twice without harm); an id that isn't a catalog item is 400; a `section` not on this shelf is 404; up to 500 items a call. `PATCH /<eid>` `{ status }` → 200 with the entry; `PATCH /<eid>` `{ section: uuid | null, index: int }` → 200 `{ positions: [{ id, position }] }` for the whole shelf after A2's renumbering (index is 0-based within the destination; past the end means last); the two bodies are distinct schemas, one call does one thing. `DELETE /<eid>` → 204 and renumber. 404 for an entry not on the caller's shelf
