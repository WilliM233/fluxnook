**Read for the Browse's kill (2.1.1 section 5, "What the fixes leave", S5).** PGlite's IndexedDB layer is Emscripten's IDBFS: `syncToFs` runs `FS.syncfs(false, ...)` after each query (`src/pglite.ts` 1186-1198 in 0.5.15's source map), and IDBFS's `reconcile` writes every changed and removed file inside one `db.transaction([IDBFS.DB_STORE_NAME], "readwrite")`. An IndexedDB transaction commits whole or not at all, so a kill leaves the store as the last whole flush left it, never between two files. On a first launch the state before the first flush is an empty `FILE_DATA`, which `refuseADamagedStore` passes (`keys.length > 0`, line 128), and PGlite starts over. So a first launch killed before its first flush reopens as a first launch: `14 migrations · 22 tables`, nothing listed, no words; and one killed after any whole flush reopens the same, since every later state heals (2.1.1's step 1 and the stand-ins' `if not exists`). S5's dead end (files and no `PG_VERSION`) needs a flush that isn't whole, which by this read a kill can't make. A read of the code, not a kill on a phone; the Browse's kill is the run, and if it shows the refusal, Q6 is L's.

A release `M.m.p` is `M * 100000000 + m * 1000000 + p * 10000` (`0.2.0` 2000000, `0.2.1` 2010000, `1.0.0` 100000000). A pre-release `M.m.p-ch.<n>.<s>` sits under its release: that release's code `- 10000 + n * 100 + s` (`0.2.0-ch.1.1` 1990101, `0.2.0-ch.1.2` 1990102, `0.3.0-ch.1.1` 2990101, above `0.2.1`'s 2010000). Minor, patch, n and s each under 100 and major under 21, so the ceiling stays under Tauri's and the Play Store's 2100000000; any other shape fails the build in words.
