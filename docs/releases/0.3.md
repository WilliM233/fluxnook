# 0.3: The nook gets a night watch

Nothing in the nook looks different. What changed is how we know it still works.

- Every change to Fluxnook is now checked by a robot before anyone reads it: style, types, tests, the database shape, and a real browser signing in.
- Each night the robot walks the whole nook in Chromium, Firefox and WebKit.
- A red check says what broke, and a failed browser run leaves a report with traces.

**Under the floorboards.** Workflow `CI` runs six jobs named for their npm scripts (`lint`, `typecheck`, `test`, `db:check`, `test:db`, `test:e2e`). The last two each start Supabase in the runner (`supabase start` with nine services excluded) and use `.env.example`, so no secrets. Actions are pinned to commit SHAs (`docs/STACK.md`), every job has a `timeout-minutes`, and the runner is `ubuntu-24.04`. `npm run db:check` runs drizzle-kit against a copy of the migrations and fails if it would write a file, or if drizzle-kit errors; it never writes to the repo. `npm run test:db` talks to Postgres through the test-only `postgres` 3.4.9 and `DATABASE_URL`, now in `.env.example`. `tests/e2e/harness/signed-in.ts` is the `signedIn` fixture: a fresh user per test, signed in through Mailpit's API. `Nightly` (04:17 UTC on `dev`, or by hand) runs one job per browser, each on its own stack, with `PLAYWRIGHT_ALL_BROWSERS=1`. Locally that switch runs all three browsers on one worker, since they share one database. Playwright has `retries: 0`, and in CI it serves a production build. `npm run check` runs the six gates locally. 36 unit tests, 2 database tests, 13 Playwright tests. Found by the Raccoon and fixed: db:check said "agree" when drizzle-kit failed on a rename, cache keys that starved the nightly, `waitForMagicLink` matching longer addresses.
