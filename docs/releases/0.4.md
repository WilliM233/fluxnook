# 0.4: The first shelf, on paper

Nothing in the nook looks different yet. The first real shelf now exists as data.

- L's Stephen King watch list (61 films, from Carrie to The Running Man) is in the repo, in list order, with each film's source note kept word for word.
- Every film carries its Letterboxd link, so it can be matched to the same film in any other list later.
- Rebuilding the shelf from the original export always gives the same file, so nobody can fix it by hand without being caught.

**Under the floorboards.** The Letterboxd export sits unedited at `supabase/seed/raw/letterboxd/stephen-king-watch-list.csv`, with a manifest in `supabase/seed/raw/README.md`. `npm run fixtures:build` turns it into `supabase/seed/fixtures/king-films.json`: 61 items of type `film` and one shelf with 61 ordered entries. Item ids are `<source>:<key>`, here `letterboxd:<boxd key>`, so the same film in a second list gets the same id. `src/fixtures/shape.ts` is the Zod shape; it also checks that ids are unique, entry positions strictly increase, URLs are https, and a `letterboxd:` id matches its URL. The CSV reader is in-repo (`scripts/fixtures/csv.mjs`), so no package was added and `docs/STACK.md` is unchanged. It normalizes CRLF before parsing, so a Windows checkout and the runner build the same bytes. `tests/unit/fixtures.test.ts` checks every file in `supabase/seed/fixtures` against the shape and against a fresh build in `node_modules/.cache/fixtures`. `npm test` is 74 tests in 14 files (36 before). The nightly's `playwright install --with-deps` step has `timeout-minutes: 10`. Found by the Raccoon and fixed: a film listed twice lost its second row's data, a Year of a single space built as 0, a list header with the wrong field count built without complaint, a stray quote in a CSV field was accepted, and `javascript:` passed as a URL.
