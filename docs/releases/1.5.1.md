# 1.5.1: The rule every write keeps

The nook has shelves in it now, and a shelf opens.

- Your nook lists your shelves as cards, newest change first, with a line of totals ("3 shelves · 398 works on them") and a strip of covers on each card.
- New shelf takes a name and a description and lands you on the new shelf's page.
- A shelf opens as a page: its name and counts, its sections, and every work numbered through the whole shelf, with its cover, type and a line of facts (a film's year and minutes, a book's form and author, a comic's series and number).
- Another person's shelf, or an id that is nothing, is a not-found page, the same as any other.

**Under the floorboards.** Nine route handlers under `/api/v1/shelves` (shelf create, update and delete; section create, update and delete; entry add, `PATCH` for a status or a move, and remove), all in `docs/API.md` with what someone would get wrong. Each write runs in one transaction under a lock on the shelf's row, renumbers the shelf 1 to n, and touches `updated_at` only when something changed. `src/lib/shelves/order.ts` is the only place a position is computed; it is pure and has no database import. A section delete moves its works above the first section before the row goes, and rolls back together if anything fails after. Another person's shelf, section or entry is 404, never 403, proved with two local accounts in `tests/db/shelves-owner.test.ts`. The fixture loader now numbers a shelf's entries 1 to n across its sections (the TMNT shelf reads 1 to 326), where it used to restart in each. `src/lib/catalog/work-line.ts` is the one formatter for a work's second line. `Thumb` gains a third size for the 48 by 72 cover. `tests/db/harness.ts` `resetComicVine` takes the loader's advisory lock, after two files loading in opposite orders deadlocked. `scripts/browse/1.5.1.sh` is the first Browse script (see `scripts/browse/README.md`). No migration, no package. `npm test` is 637 tests (541 at 1.4.3), `test:db` 225 (173), e2e 95 listed (84). `package.json` is `0.1.0-ch.5.1`. The Raccoon found, and the chapter fixed: a test file that skipped the order check after three writes, an add that refused `section: null` where a move takes it, an unchanged write that moved a shelf to the top of the nook, a NUL byte in a name answering 500, an upper-case id in a move answering 500, and "carrie" landing beside "Carrie" as a section name.

**Not yet.** Nothing on the shelf page is a button: Add works, New section, Rename, Edit shelf, Delete shelf, Delete section, Remove, the drag and the status control are 1.5.2's, so for now those writes are the routes only. The dim line "Drag it into one, or leave it." prints under works above the first section before there is anything to drag; 1.5.2 brings the grip. The Add to shelf sheet on the item page, its chips as links, Add the run on the series page, the import sheet's line, and `GET /api/v1/shelves` are 1.5.3's, with the chapter's end-to-end Browse. Sharing a shelf by link waits for Volume 2. The shelf page renders every row on one request with no paging; the plan's Deferrals name the trigger. The database's foreign key still cascades a section row's entries on a hand-written delete, since this chapter adds no migration.
