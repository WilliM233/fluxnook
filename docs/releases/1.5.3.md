# 1.5.3: Three doors

Works get onto shelves from where you find them.

- On any item's page, Add to shelf picks a shelf and a section, or makes a new shelf on the spot. Shelves that already hold the work say so, with its number.
- On a shelf with sections, the Into choice that keeps a work out of them reads "No section", here and in a shelf's own Add works. Those works sit above the first section, so "At the end" pointed the wrong way. A shelf with no sections still says At the end.
- The shelves on an item's page are links now: "Stephen King, publication order · #1" takes you to that shelf.
- On a comic series' page, Add the run to a shelf puts every issue on a shelf in cover-date order. Issues already there stay where they are, and the page tells you how many went in and how many were already there.
- Adding a comic series on the import sheet with the "same as a run you entered by hand?" select left on No now stops and asks once, so a run you already have isn't doubled by a stray click.

**Under the floorboards.** One read route, `GET /api/v1/shelves` with `?item=` and `?items=`, answers the sheet: the caller's shelves in the nook's order with counts, sections and `has`, how many of the works asked about the shelf holds. `?items=` takes up to 200 uuids, not the 500 the spec named: the session cookie shares Node's header limit with the URL and 500 never reached the route. The sheet asks about a longer run in chunks of 200 and adds up `has`. One sheet, `shelves/add-to-shelf.tsx`, serves both pages and fetches when it opens, so a 326-row shelf page carries no shelf list. On the item page the fresh `has` decides which rows are disabled; the chips only give the number. "Or a new shelf" is two calls (make, then add); if the second is refused the sheet says the shelf was made and a retry fills it. A key given twice in the query is a 400. No migration, no dependency, no write changed. `scripts/browse/1.5.3.sh` is the chapter's exit Browse; it writes its hands-on steps to `browse-results/1.5.3-steps.md` before the first pause, and 1.5.1's script now reports to `browse-results/` too. `package.json` is `0.1.0-ch.5.3`. The Raccoon found, and the chapter fixed: the 200 cap (a 350-issue run opened a dead sheet), a page left open in another tab disabling the wrong shelves, and a failed second call that never said the shelf was made.

**Not yet.** The series page's result line is gone on reload; its link to the shelf is the way on. The shelf page's payload is still heavy: the TMNT page measured 1,241,994 bytes warm on `next dev` in the exit script, and 1,236,237 on a production build, past the 1 MB at which paging a long shelf is due; when it lands is still to be decided. The `?series=` form of the route waits for a series past 1,000 issues. Sharing a shelf by link waits for Volume 2.
