# 1.2: The first screens

The nook has a face now, and a way to fill it. Search TMDB, add a film or a show, open its page.

- Search for a film or a show and see at a glance which results are already in your catalog, which look like something you have, and which are new.
- Add one with a click. The poster comes with it.
- When a result looks like something already there (say, a film from your Letterboxd list), a sheet shows both side by side. Say "same" and the TMDB details are added to the item you have. Say "different" and it becomes a second item.
- Every item has a page: cover, facts, release date, where it came from, what it is connected to (a film shows the book it adapts), and which of your shelves hold it.
- For things no provider knows, a plain form adds an item by hand: a film, a show, a book or a comic.
- The nook is dark now: near-black violet, one lavender accent, Fraunces for titles. Item pages stack the cover above the facts on a phone.

**Under the floorboards.** Schema: `tv` joins the item types, `items` gains `summary` and `cover_path`, and `item_films` and `item_tv` hold the type columns. Three migrations, each opening with its Down: `film_tv` (generated), `film_tv_updated_at` and `covers_bucket` (a public Storage bucket, `covers`, a row in `storage.buckets`). The bucket has no write policy; only the server writes, with `SUPABASE_SECRET_KEY`. `src/lib/providers/tmdb.ts` is the TMDB client; `TMDB_API_KEY` (the v4 read token) and the secret key are read through `readServerEnv`, optional and server-only, and `TMDB_BASE_URL` and `TMDB_IMAGE_BASE_URL` default to TMDB's own. Three routes: `GET /api/v1/providers/tmdb/search`, `POST /api/v1/items/import`, `POST /api/v1/items` (see `docs/API.md`). TMDB keys carry the kind (`movie/133805`); import is idempotent by key and an attach never replaces a held title, summary or differing-year date. A TMDB collection becomes a franchise on import. The signed-in pages sit in the `(app)` route group, which holds the one sign-in guard, the header and the footer with TMDB's attribution. Tests run on recordings in `tests/fixtures/tmdb` served by a stub (`npm run tmdb:stub`, `tests/stub/tmdb.ts`); CI holds no TMDB token and its stack now runs `storage-api`, with the secret key taken from `supabase status`. `npm run tmdb:record` re-records. Locally Playwright runs two workers: ten starved `next dev`. The Raccoon found, and the chapter fixed: `movie/0133805` imported the same film under a second key, and an attach could join an item that didn't look like the result. `npm test` is 243 tests (190 before), `test:db` 66 (34), e2e 33 (13). `package.json` is `0.1.0-ch.2`. No package was added; `badge`, `dialog` and `textarea` were copied in from shadcn.
