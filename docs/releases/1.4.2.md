# 1.4.2: The run comes in

You can add a comic series from Comic Vine now, with every issue it lists, and open it as a page of its own.

- A Comics search row has an Add button when the series is new to you or looks like one you have. It opens a sheet: are these single issues or collected editions (and in which format), and is this a run you already added by hand?
- Say Same and Comic Vine's details, covers and dates go onto the issues you entered yourself, matched by issue number. Your titles are never changed. Say Different and you get a second run beside yours.
- A series Comic Vine names in a way no search can match ("Tales of the TMNT" for your "Tales of the Teenage Mutant Ninja Turtles Vol. 2") has a "Same as a run you added by hand?" menu. Pick yours and the issues join it.
- The series has a page: its years, publisher and description, and a grid of its issues in cover-date order, each with its cover and a link to the issue. The search row then says In your catalog and Open goes there.
- If you add the wrong kind (collected editions onto a run of single issues, or the reverse), or a run that already belongs to another Comic Vine series, the sheet says so and nothing is written.

**Under the floorboards.** New route `POST /api/v1/series/import` (see `docs/API.md`), Zod-validated, strict. `src/lib/catalog/series.ts` is the import: the volume and every issue are fetched first, then written in one transaction (a `series` row, its `series_sources` row, each issue as a comic with `series_id`); covers follow after the commit, four at a time, and a failure is one log line naming the key. Idempotent by volume key, race-safe on the source claim. `attachTo` is `{ series }` (by series text, matched by number, no name check) or `{ collected }` (by title stem, held to the search's name rule). Held titles, form and series text are never written. `GET /api/v1/providers/comicvine/search` now answers `{ results, groups }`; `seriesGroups` in `match.ts` is split out of `seriesStatuses` and shared. `/series/<uuid>` is a server component (`series-page.ts` reads it). The sheet is `series-sheet.tsx`, a sibling of the match sheet. The Comic Vine stub answers 500 naming the file when an issues recording is missing (it was an empty list), 404s a cover whose file name starts with `missing-`, and takes `--dir`. Two recordings added: the issues of volume 18785 and the "tales of the tmnt" search. `tests/reset-comicvine.ts` is the one reset both the db and e2e harnesses use. `tests/db/fixtures-load.test.ts` now counts only `manual` edition sources, since an import adds `comicvine` ones. The Raccoon found, and the chapter fixed: collected editions could be attached under single issues and the reverse (62 hardcovers on the fixture's issues in one click); a 503 from a gateway with no JSON body left the sheet silent; a label of any length was accepted; two comics numbered alike in one run left the second one unreachable. `npm test` is 510 tests (472 at 1.4.1), `test:db` 152 (117), e2e 72 listed (61). `package.json` is `0.1.0-ch.4.2`. No package was added, no migration.

**Not yet.** The Collected in section of a series page, issue pages and the contents of collected editions: 1.4.3. The series cover is stored and not shown; waits for the first screen that lists series. Comic Vine's one-line description often repeats the volume number, so the page can read "Vol. 1. Volume 1."; left as Comic Vine says it until it bothers someone. No undo for a wrong Same, and no check by name on a `{ series }` pick; waits for the first wrong pick. A series row's kind (Ongoing and so on) is never set by an import.
