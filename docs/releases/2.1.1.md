# 2.1.1: The stub on PGlite

This is a stub in a browser, not the app on a phone yet. Nothing in the nook you use today changed.

- A small page now keeps shelves with no server at all: type a name, press Add, and the shelf is listed.
- Reload the page and the shelf is still there. It lives in the browser, on your own machine.
- The page says how many migrations it ran and how many tables it holds, and which build it is. Today that reads 14 migrations, 22 tables.
- If it can't open its database, it says so in words, with the build's version, instead of showing a blank page.
- A name the nook would refuse is refused here too: blank, over 120 characters, or with a NUL in it.

**Under the floorboards.** `device/` is new, built by Vite and not Next; `src/`, `supabase/` and `.github/` are untouched (`git diff --stat origin/dev -- src supabase .github` prints nothing). `@electric-sql/pglite` 0.5.15 is the device's Postgres (18.6 by `select version()`; hosted is pinned at 17 in `supabase/config.toml`), and `@tailwindcss/vite` 4.3.3 keeps the Deep Field look. The 14 migrations run unedited through Drizzle's migrator over a list `device/migrations-plugin.ts` reads from `supabase/migrations` at build, in one transaction. Two empty stand-ins, `auth.users` and `storage.buckets`, are made first because three statements in the migrations name them; the signup trigger then makes the device person's `profiles` row. The data name `idb://fluxnook` and the person's fixed id are part of the app's identity: change either and a phone opens empty with no error, and `tests/unit/rummage-device.test.ts` pins both. A migration chunk must be one statement and its `when` must keep increasing; `device-migrate.test.ts` goes red in `npm test` on either. `playwright.config.ts` now starts a second server (`npm run device:build && npm run device:preview`, port 4173) and its `webServer` is an array, so `tests/unit/rummage-playwright-config.test.ts` finds the app's entry in it and `tests/unit/rummage-device.test.ts` pins every server's `reuseExistingServer` off in CI. The stub spec runs in Chromium only. `scripts/browse/2.1.1.sh` is the Browse. `package.json` is `0.2.0-ch.1.1`. The Raccoon found, and the chapter fixed: a refused flush saving a shelf the page called unsaved (the add now takes the row back), letters lost while an add was out (the field stays live), the alert printing SQL (it prints the cause), a stray rejection condemning a good database (only load failures count), a 120-character name pushing a phone sideways, a second window overwriting the first (a Web Lock refuses it in words), a store missing `PG_VERSION` opening empty (it refuses in words), no request to keep the store, and a failed open dropping the version.

**Not yet.** The Android and Windows builds, signing, and the README's install note: 2.1.2. A migration applied over a phone's rows has no witness, since the catch-up test runs over empty tables: the first migration after this chapter. Fraunces and Inter: the page uses the stacks in `docs/designs/deep-field/tokens.json` until Chapter 2.2 brings the real pages. A Content-Security-Policy in `tauri.conf.json` has to allow PGlite's direct `eval`: 2.1.2. Whether the Web Lock and the request to keep the store exist in the shell's web view (`navigator.locks` needs a secure context): read on 2.1.2's phone and Windows build. A page that never gets an answer from IndexedDB stays on a disabled field with no words. L's hands walk is once, at 2.1.2.
